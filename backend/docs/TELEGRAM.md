# Telegram-бот: уведомления о новых инцидентах

## Как это работает
```
 Пользователь в Telegram                 Наш бэкенд
 ───────────────────────                 ──────────
 /start  ───────────────────────────────► бот (python -m app.bot) отвечает кнопкой «Войти»
 жмёт «Войти» ──► открывается мини-апп ─► GET  https://<PUBLIC_BASE_URL>/tg/app
 вводит логин/пароль от сайта ──────────► POST /api/tg/link {initData, email, password}
                                           1) проверка подписи initData токеном бота
                                           2) проверка пароля (та же, что на сайте)
                                           3) users.telegramChatId = id, канал telegram = вкл
 мини-апп закрывается, в чат приходит «✅ Готово»
 ...
 новый инцидент в файле/ITSM ───────────► воркер: событие incident.created → правило incident.new
 сообщение в Telegram  ◄────────────────── sendMessage (HTML, кнопка «Открыть в ITSM»)
```
- **Мини-апп входит по тем же логину и паролю, что сайт**: одна база пользователей, одна проверка, тот же лимит попыток.
- **initData** — строка, которую Telegram передаёт мини-аппу. Она подписана токеном бота, поэтому подменить Telegram-id нельзя. Проверка — `services/telegram.py::verify_init_data` (по документации Telegram, с тестами).
- **Отправка уведомлений идёт из воркера**, а не из бота. Бот только отвечает на команды, и его перезапуск не теряет уведомления.
- Какие уведомления придут: `incident.new` (новый инцидент), `critical.new`, `critical.resolved`, `coordinators.assigned`, `high.new`, `sla.danger`, `sla.breached`. Виды отключаются в профиле на сайте (`PATCH /api/me` → `notificationSettings.kinds`).
- Если пользователь заблокировал бота, его чат отвязывается автоматически.

## Что сделать (по шагам)

### 1. Токен — в .env, и больше никуда
```
TELEGRAM_BOT_TOKEN=<токен от @BotFather>
```
`.env` в `.gitignore`. Токен не должен попадать в код, в git и в чаты. Если он где-то засветился, в @BotFather выполните `/revoke`, получите новый и замените его в `.env`.

### 2. HTTPS-адрес для мини-аппа (туннель)
Telegram открывает мини-апп **только по https**, а localhost ему недоступен. Самый простой вариант — бесплатный туннель Cloudflare: без регистрации и без страницы-предупреждения (у бесплатного ngrok она есть и ломает мини-апп).

Установка:
- Windows: `winget install --id Cloudflare.cloudflared`
- macOS: `brew install cloudflared`
- Linux: пакет с github.com/cloudflare/cloudflared/releases

Запуск (отдельный терминал, API должен работать на 8000):
```bash
cloudflared tunnel --url http://localhost:8000
```
В выводе будет адрес вида `https://random-words.trycloudflare.com`. Пропишите его в `.env`:
```
PUBLIC_BASE_URL=https://random-words.trycloudflare.com
# чтобы кнопка «Открыть в ITSM» в Telegram тоже работала (localhost Telegram не принимает):
ITSM_BASE_URL=https://random-words.trycloudflare.com/itsm/incident/
```
⚠️ Быстрый туннель даёт **новый адрес при каждом запуске**. После перезапуска туннеля обновите `.env` и перезапустите API, воркер и бота.

### 3. Запустить бота (третий процесс)
```bash
uv run python -m app.bot
```
В логе должно появиться `bot started` с username бота и адресом мини-аппа. API и воркер тоже должны быть запущены. В Docker бот запускается сам — сервис `bot`.

### 4. Проверить
1. В Telegram найдите бота → `/start` → «Войти».
2. Введите `coord1@example.com` / `demo12345` → «Готово», мини-апп закрывается, в чате подтверждение.
3. `/status` покажет, к кому привязан чат.
4. Добавьте инцидент: `uv run python -m scripts.demo new-critical` или вручную в `data/incidents.json` → через секунду в Telegram придёт уведомление.
5. `/stop` — отключить уведомления.

## Если не работает
| Симптом | Что проверить |
|---|---|
| В ответ на /start нет кнопки «Войти», есть предупреждение | не задан `PUBLIC_BASE_URL` или он не https; перезапустите бота |
| Мини-апп пишет «Откройте эту страницу кнопкой в боте» | страницу открыли в браузере, а не из Telegram |
| «подпись initData неверна» | у API и бота разные `TELEGRAM_BOT_TOKEN`, или токен сменили — перезапустите API |
| «initData устарел» | мини-апп долго висел открытым — закройте и откройте снова |
| Мини-апп не открывается / белый экран | не запущен туннель, или в `.env` старый адрес туннеля |
| Привязалось, но уведомления не приходят | не запущен воркер; в логе воркера `telegram send failed` — смотрите текст ошибки |
| `TelegramConflictError` в логе бота | бот запущен дважды (например, у двух человек в команде с одним токеном) — оставьте один |

Важно: один токен — один запущенный бот. Если бэкенд запускают несколько человек, бот с этим токеном держит кто-то один, например на машине для демо.

## Файлы
- `app/bot/__main__.py` — бот (aiogram 3): /start, /status, /stop, кнопка меню «Войти»
- `app/api/routes/tg.py` — страница мини-аппа `/tg/app`, `POST /api/tg/link`, `POST /api/tg/unlink`
- `app/services/telegram.py` — проверка initData, привязка, форматирование и отправка
- `app/services/notify.py` — правила: какие события порождают уведомления
